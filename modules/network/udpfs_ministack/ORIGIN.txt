Vendored from rickgaiser/neutrino iop/ministack/, pinned to commit
06188cce7cd07d2a158cb4b2646c5719fc16a565. Mini IP/UDP stack for the UDPFS transport chain
(parses the ip= arg -> the PS2's own static IP; no DHCP). See ../udpfs_bd/ORIGIN.txt for the
full UDPFS provenance + local changes (PS2SDK Makefile, clang-format).

Local build fix (ps2dev:latest iopfixup): exports.o is listed FIRST in the Makefile's IOP_OBJS
and _retonly is defined AFTER the export table in src/exports.tab, so iopfixup doesn't reject
_retonly as a value-0 .text symbol. Same fix as udpfs_smap / smap_udpbd (commit 2139bcde). The
export table stays POPULATED -- udpfs_bd imports its udp_* functions -- so it must NOT be emptied.
Keep both on re-vendor.

Public parity port (#921), Open-PS2-Loader commit
6d04b40e8d857368110265a18ec9fc90b7c316c4: announce our IP/MAC with a gratuitous
ARP before broadcasts from bound sockets, so discovery's unicast reply can reach
the PS2 after a stale server ARP entry. Unbound udptty and unicast do not announce.
No export-table change; arp_announce is internal to the ministack module.
Local IP-conflict telemetry ported from Open-PS2-Loader #922 (0a1a593a): record another MAC claiming
our IP, never cache our own address, append arp_ip_conflict to export slot 7 (slots 4-6 unchanged).
udpfs_ioman queries this record without network traffic. Real-source host test:
../udpfs_shared/tests/test_ministack_conflict.c. Keep this change when re-vendoring.
